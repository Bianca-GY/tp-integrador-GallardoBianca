# ADR-002 — Límite de cuatro butacas ocupantes por usuario

## Estado

Aceptado.

## Contexto

El nuevo requerimiento de negocio establece:

> Un usuario no puede tener más de cuatro butacas ocupantes en un mismo evento.

La regla es de tipo agregado porque el límite depende de la cantidad de
butacas ocupantes que tiene un mismo usuario dentro de un evento.

No puede resolverse únicamente mediante una restricción de unicidad sobre una
fila, ya que la condición involucra múltiples retenciones pertenecientes al
mismo usuario y evento.

## Decisiones

### 1. Identificador de la regla

La nueva regla se identifica como:

**RET-002**

Su definición es:

> Un usuario no puede tener más de cuatro butacas ocupantes en un mismo evento.

### 2. Definición de butaca ocupante

Para RET-002 se consideran ocupantes las retenciones en estado:

- `ACTIVE`
- `CONFIRMED`

No se consideran ocupantes:

- `EXPIRED`
- `RELEASED`

Por lo tanto, una retención confirmada continúa ocupando capacidad del usuario,
mientras que una retención expirada o liberada deja de contar.

### 3. Límite

El máximo permitido es de **cuatro butacas ocupantes por usuario y evento**.

Cuando el usuario ya posee cuatro butacas ocupantes, una nueva solicitud de
retención debe ser rechazada.

No se realiza una creación parcial.

### 4. Identificación del usuario

El starter no posee autenticación real y la autenticación está fuera del
alcance definido para esta etapa.

Para poder expresar RET-002 en el dominio y verificarla mediante pruebas, el
endpoint recibe un campo:

```json
{
  "seat_id": "butaca-1",
  "user_id": "usuario-1"
}
